### Hook handler types (confirmed 5)
`command`, `http`, `mcp_tool`, `prompt` (30s timeout), `agent` (60s timeout, experimental).

### Hook fields (current)
- `args` array: exec form — invokes via execve, no shell interpolation. Use for simple hooks.
- `async` boolean: background, no wake on exit 2
- `asyncRewake` boolean: background, wakes Claude on exit 2; stderr shown as system reminder
- `once` boolean: remove after first successful run (skill frontmatter only; ignored in settings files)
- `timeout` number: seconds; 600 default for command/http/mcp_tool; lowered on UserPromptSubmit, MessageDisplay
- `statusMessage` string: custom spinner text

New settings.json fields: `disableAllHooks`, `allowedHttpHookUrls`, `httpHookAllowedEnvVars`, `allowManagedHooksOnly`.

### PostCompact context injection (confirmed)
PostCompact's stdout IS injected as context after compaction completes. JSON output can set `watchPaths`, reload skills, or supply `initialUserMessage`. PostCompact discards `systemMessage` and `additionalContext` (Stop-pattern fields). PreCompact can block (exit 2 prevents compaction). Current scaffold uses `SessionStart(source: compact)` — still valid and additionally covers resume/startup.

### SubagentStop
Fires when a subagent terminates. Can block (exit 2). Receives `agent_id`, `agent_type`, `last_assistant_message`. Matcher supports agent-type strings and plugin-scoped patterns (e.g. `^my-plugin:reviewer$`).

### Stop hook loop guard
No numeric block cap documented in official sources. Loop prevention relies on `stop_hook_active` field in stdin JSON — seeded stop-checks scripts must exit 0 when it is true before running tests. Without this guard a failing-test Stop hook can loop indefinitely.

## Loop engineering — community/team practice

**CONSENSUS** — >=3 independent credible sources (becomes Step 3H check):
- Five required loop parts: (1) trigger, (2) verifiable goal, (3) execution phase using named skills, (4) verification step, (5) stopping rule with a named terminal state (success, no-op, blocked, stalled, exhausted).
- Multiple independent exits: goal verifier + hard iteration cap + token/cost budget — any one tripping stops the loop.
- Trust deterministic verifier (tests, linter, checksum), never agent self-report for loop termination.
- No-progress detection: exit if output state unchanged across iterations.
- Human-in-the-loop checkpoints required for irreversible actions (deploy, send, delete).
- Define termination criteria before the loop starts using verifiable automated checks.

**RECOMMENDED** — team/AAIF guidance:
- Token/cost budget as a hard spending limit per run, built in from day one.
- Checkable goals ("make tests pass") vs. uncheckable goals ("improve code") — uncheckable goals have no verifiable stop condition; avoid.
- Scheduled self-prompting via cron hooks or `asyncRewake` for polling/monitoring loops.
- Combined prompt caching + loop pattern reduces total loop costs 60-80%.

**EMERGING** — single credible source (track only):
- Loop goal formulation as a formal spec step (arxiv 2607.00038, July 2026): structured loop specification replaces step-by-step prompting; improves autonomous task completion.
