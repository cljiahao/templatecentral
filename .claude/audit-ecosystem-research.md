### Community consensus & team recommendations

**RECOMMENDED** (official docs):
- Exec-form hooks: string `command` + `args`, script paths via `${CLAUDE_PROJECT_DIR}`.
- PostToolUse feedback via `additionalContext`; Stop hooks run deterministic checks and exit 2; guard with `stop_hook_active`.
- Secrets: `Read(./.env)` / `Read(./.env.*)` deny rules, optionally paired with sandbox; do not rely on Bash deny rules.
- Keep CLAUDE.md short; use hooks for must-happen rules, skills for on-demand knowledge; give Claude a pass/fail verifier (`/goal`, Stop hook, adversarial review subagent).

**CONSENSUS**:
- PostToolUse feedback-only (never blocks); Stop gate exits 2 on failure.
- Do not pipe hook output through `tail` without capturing the exit code.
- Trust deterministic verifiers, not agent self-report, for loop termination.

**CONSENSUS anti-patterns**:
- Array-valued `command` (silently ignored) — now lint-enforced.
- Relative hook script paths (break after `cd`).
- Bare `pytest`; hardcoded plugin paths; `continueOnBlock` (not a key).
- Using `updatedToolOutput` to "undo" a tool — prevent in PreToolUse instead.

**EMERGING** (track only):
- `onFailure: "block"` hook option; Mods extension system (v2.1.287); PreModelSwitch/PostModelSwitch harness uses.

## Loop engineering — community/team practice

**RECOMMENDED** — official docs:
- `/goal`: model evaluator checks a condition (≤4,000 chars) after each turn; stall guard; 3 automatic retries then pause; idle check-ins 30m → 1h → every 2h (max 3). No built-in token budget — put a turn cap in the condition ("or stop after 20 turns"). `CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0` disables check-ins/retries.
- `/loop`: dynamic delay 1 min–1 h; bare `/loop` runs `.claude/loop.md` (25,000-byte cap) or a built-in maintenance prompt; fixed-interval tasks expire after 7 days; ≤50 tasks/session; no catch-up for missed fires; `CLAUDE_CODE_DISABLE_CRON=1` disables.
- Cloud routines: minimum interval 1 h.
- Start with the simplest loop that could work; hard spend limits per run.

**CONSENSUS**:
- Multiple independent exits: deterministic goal verifier + hard iteration cap + budget.
- No-progress detection; per-tool retry limits; human checkpoints before irreversible actions.
- Define termination criteria before the loop starts.

**EMERGING**:
- Checkable vs uncheckable goals — avoid loops whose goal has no verifiable stop condition.
