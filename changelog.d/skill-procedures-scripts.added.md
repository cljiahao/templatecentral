- Two skill procedures are scripts: `skills/review/review/review-scope.sh` prints the review scope (files committed since the baseline commit plus the session files) and records `.claude/review-baseline.md` only with `--record-baseline`, and `skills/cleanup/remove-example/remove-example.sh` removes the scaffold example from a project per stack manifest (dry run by default, `--apply` writes, a modified example file is kept unless named with `--force <path>`); both fail closed before any write and have tests (`scripts/review-scope.test.sh`, `scripts/remove-example.test.sh`, `scripts/remove-example-edge.test.sh`). `remove-example.sh` rolls back on INT, TERM or HUP (exit 130, 143, 129; `ROLLBACK INCOMPLETE` and a kept temp directory if the rollback fails), moves each file aside and compares it with the copy taken during the checks before it deletes or replaces it (forced files too, so a change made after the checks is never lost), rejects duplicate or nested delete rows, reads the stack from line 1 of `AGENTS.md`, and writes BLOCK and NOTE lines to stderr; `review-scope.sh` ignores `GIT_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE`, accepts the `<project>/` prefix form only for an absolute project path, `--record-baseline` takes `--at <sha>`, and the committed baseline file is left out of its own scope.
