- The here-string lint reads no shell syntax any more: a seeded pipefail script or hook that has `<<<` on any line fails with its file and line, except a full-line comment or a row in the `HERE_STRING_ALLOW` list in `lint-skills.sh` (exact file and line text; a row that matches nothing fails too). It scans the seeded `.sh`, `.envsh`, `.yml` and `.yaml` files, so CI pipeline files that set pipefail are covered. A line is a comment only when it starts with `#` after spaces or tabs and the line before does not end in a backslash; Unicode blanks (U+00A0, U+2028, `\x85`, `\x1c`-`\x1f`) are not blanks to bash and no longer hide a here-string. Heredoc and arithmetic guessing is gone, so no shift, quote or heredoc form can hide a here-string. Files are read with their carriage returns kept and split on newline only, so a lone CR no longer ends a line (`grep -q x<CR># <<< "$v"` is a hit, bash runs it); a CRLF file still hits on a real `<<<` and stays clean on a real comment, and a backslash before CR still joins the next line.
