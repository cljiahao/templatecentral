- Seeded in-session code review (wired by the entry above): a read-only `code-reviewer` subagent (`.claude/agents/code-reviewer.md`, tools Read, Grep, Glob; it opens no secret files and redacts any secret in the diff) reads `.claude/review/current.diff` against `.claude/review-checklist.txt` plus a per-stack list and ends with `VERDICT: pass|fail`; a clean pass needs a `FINDINGS: none` line. `scripts/record-review.sh --prepare` writes the diff; `scripts/record-review.sh <file>` refuses a stale `current.diff`, a verdict that is not the last line, a pass with any blocker or major finding line (any prefix, any case, CRLF stripped) and a dirty tree, then writes the gitignored `.claude/review/<sha>.record`. `scripts/check-review-record.sh` fails closed when the diff cannot be computed (no merge base, shallow clone, empty diff, base equal to HEAD), hashes the diff independent of user git config, takes the base from an argument or `TC_REVIEW_BASE`, then `origin/main`, then `origin/master` (never the upstream), rejects CRLF and duplicate keys in a record, and skips only on `GITHUB_ACTIONS=true` or `TF_BUILD=True` (a bare `CI=1` or `GITHUB_ACTIONS=false` still enforces). The record stores the merge base, and the gate re-resolves the base and fails when it differs from the recorded one. A missing hash tool exits 2. Only the record for HEAD is checked, so a push of another ref is not covered. The record is an honesty aid inside one session, not a security boundary. No login, key or hosted service. Tests: `scripts/seeded-review-gate.test.sh`.
