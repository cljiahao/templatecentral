- Seeded duplicate-test check, new files only and not wired into any gate yet: `scripts/check-duplicate-tests.sh [project-dir]` with helpers `duplicate-tests-ts.mjs` (the project's own `typescript` 5.x or 6.x, read from its `node_modules` only) and `duplicate_tests_py.py` (`ast` and `tokenize`, run with `.venv/bin/python3` when the project has one). It compares the bodies of whole-project test cases as token sequences, ignoring comments, whitespace and titles: Vitest/Jest-style `it`/`test` (also under an import alias, `@jest/globals`, a namespace import, `.only`/`.skip`/`.concurrent`, inside `if`, `try` or helper functions, and `it('a', handler)` when the handler is defined in the same file; any other named handler is counted and printed as a NOTE), pytest and unittest cases (`test*` functions and methods in `Test*` classes or `TestCase` subclasses), in `*.test.*`, `*.spec.*`, `*-test.*`, `*-spec.*` (including `*.e2e-spec.ts`), `__tests__`, `test*.py` and `*_test.py` files, symlinks included when the target is inside the project. Rule 1 fails on identical bodies with the identical context (fix: delete one). The context is the imports, constants, helpers and fixtures the body names (and what those name, transitively) at the top level and in each enclosing describe or class, every other statement that runs around the case (hooks, mocks, patches, assignments such as `process.env.MODE = 'a'` or `os.environ["MODE"] = "a"`, autouse fixtures), loop headers and loop data, the case's own decorators, parameters and parameter table, and for pytest every `conftest.py` up to the project root; a top-level statement the body does not name, such as an unrelated import or constant, is not context; relative import paths count as project paths, titles never count. Rule 2 fails when `SHAPE_GROUP_MIN` (3) or more cases of one file with the same context match once strings, numbers and booleans are placeholders (fix: `it.each` / `test.each` / `pytest.mark.parametrize`), prints a NOTE at two, and skips bodies under `MIN_BODY_TOKENS` (30) tokens. Parameterised cases (`it.each`, `it.for`, tagged-template tables, `pytest.mark.parametrize`) are compared with their table in the key, and a table that repeats a row fails, also when the table is a constant (a TypeScript one resolved through the enclosing scopes of the `each` call, a Python one assigned once at module level; anything not resolvable to one same-file array is not row-checked) or is wrapped in `as const`, `satisfies` or parentheses; `ids=` and the `id=` of `pytest.param` are not part of the key. A declaration or assignment that calls something or awaits and that no test in its scope names counts as context, since it can have an effect. The failure message for rule 2 says to merge the cases into one parameterised test and names every case with file and line. Inside a git work tree the files read are `git ls-files -co --exclude-standard` (tracked, plus untracked and not ignored), so ignored build output drops out and a tracked test is never skipped by its folder name; outside a git work tree everything is read and one NOTE says build output was not filtered because the project is not a git repository. `node_modules`, `.git`, `.venv`, `venv` and any folder with a `pyvenv.cfg` are skipped at any depth in both cases. Also read: `*.cy.ts(x)`, `*.cy.js`, `*.cy.jsx`, `*.cy.mjs`, `*.test-d.ts(x)`, `.cjs`/`.cts` under `__tests__`, and the `xit`, `xtest`, `xdescribe`, `fit`, `fdescribe` and `context` names. Accepted limits: a no-op statement or a reordered body defeats rule 1, and splitting same-shape cases across files defeats rule 2. Exit 0 clean or an empty project that declares no tests (printed as "nothing to check"), 1 findings, 2 cannot run (no node, python3 or supported `typescript`, unparsable or unreadable file, a NUL byte in a Python file, a test file name with a tab or newline, test files with no case at all, a declared test script or config at any depth with no test file found, cases read but none compared, with the message saying how many were todo or bodyless). No ignore comment and no environment switch. `scripts/seeded-duplicate-tests.test.sh` covers both languages and installs the `typescript` version pinned in `versions.txt` into a reusable temporary folder (or uses `TC_TEST_TYPESCRIPT_DIR`); the git file list is intersected in one pass (a test asserts the number of started commands does not grow with the file count); a project path that is a symlink is followed; test files that exist but are all git-ignored stop the run (exit 2); a parameter table is row-checked only when every reference to it in its scope is a plain read (the declaration, each(T), T.length), for TypeScript and Python alike; test files inside a nested git repository are not checked and get a NOTE; a git failure other than "not a git repository" stops the run. Measured CPU time: 2000 cases in 40 files about 0.7 s, 5000 cases in one file about 0.8 s (TS) and 1.1 s (Python).
