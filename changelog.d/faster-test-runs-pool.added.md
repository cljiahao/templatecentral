- Faster test runs with every check kept. `scripts/lint-skills.test.sh` runs its probes in a bounded pool (default the CPU count, `LINT_TEST_JOBS` a whole number from 1 to 256, anything else exits 2 before a temp dir exists; `1` is strictly serial, the parent-side checks included) with no batch barrier; each probe has its own process group, copy and result file, results print in the original probe order, and the output is identical to the serial run. A probe that crashes, is killed, leaves an empty or truncated result, or is missing counts as FAIL (a missing count is reported). The pool stops its probes' process groups itself at exit, interrupt and reap time, without `ps`, and keeps the work dir with a warning when a group cannot be confirmed gone. `scripts/lint-skills-pool.test.sh` proves each of those without reading a clock (FIFOs, not sleeps), the `LINT_TEST_JOBS` values, cleanup with `ps` present, absent and failing, and that each case fails when its guard is removed. The CI job `shell-lint` is split into parallel jobs so none runs near its timeout, with every step kept and run once; each job installs only the tools it needs, and a new `All checks` job requires every job and fails when a job id of the workflow (read by `scripts/workflow-job-ids.sh`, which fails on a job key it cannot read) is missing from its `needs`. Probes read `/dev/null` as stdin, so a probe that reads input cannot stop the pool on a terminal. `scripts/check-tests-wired.sh` fails when a `scripts/*.test.sh`, `scripts/test-*.sh` or `adapters/*/*.test.mjs` is not run by a workflow step that runs on pull requests: it parses the workflow YAML and counts a run block only when every line of it is a blank line or a plain `bash scripts/<name>` or `node adapters/<dir>/<name>` command (so a heredoc, quote, function, branch, loop, continuation, `exit`, `trap`, `set`, comment or list operator wires nothing), and not a step with `if:`, `shell`, `working-directory` or `continue-on-error`, a job or workflow with `defaults.run`, a step, job or workflow `env` holding a name off a closed list (BASH_ENV and the like), or a workflow whose `pull_request` trigger has `branches`, `branches-ignore`, `paths`, `paths-ignore` or a `types` list other than the one in use (so the validate workflow no longer path-filters its pull_request trigger and runs on every pull request); an unparsable workflow fails closed (`scripts/check-tests-wired.test.sh` plants each bypass beside a clean control); `check-sonar-parity.test.sh`, `defect-report.test.sh` and `migrate-baseline.test.sh` now run in CI, and `lint-skills.test.sh` runs with the default pool.
