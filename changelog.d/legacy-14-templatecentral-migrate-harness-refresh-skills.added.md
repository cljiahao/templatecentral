- `templatecentral:migrate` harness refresh: `skills/migrate/general/harness-refresh.sh` brings a project that already carries a harness to the current templates. Dry run by default (one line per file: SAME, REPLACE, MODIFIED, ADD, GONE); `--apply` adds missing files, replaces only files whose hash equals the `origin_hash` in `.claude/harness.json` and that match their `.claude/.harness-base/` copy, writes `<path>.templatecentral-new` beside every other changed file, never deletes, refuses a dirty git tree without `--allow-dirty`, refreshes the records of what it wrote, runs `harness-live.sh`, and with `--baseline <dir>` runs the quality baseline before and after and compares. Exits 1 when a file needs the user. A project without both records gets its changed files as MODIFIED. `scripts/harness-refresh.test.sh` covers each class, the dry run, the refusals, paths with spaces and symlinks; it runs in CI. `--apply` checks every path it writes first and refuses with exit 2 on a symlink or an outside path, re-hashes each replaced file just before writing, never overwrites an existing `.templatecentral-new`, writes `harness.json` through a temp file and rename, and ends a partial run with a `PARTIAL:` line.
