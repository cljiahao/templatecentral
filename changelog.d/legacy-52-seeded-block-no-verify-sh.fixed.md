- Seeded `block-no-verify.sh` no longer lets a guarded command pass inside an interpreter or a blind shell: inline `python -c`, `node -e`, `perl -e`, `ruby -e`, `deno eval` code is scanned with the same checks as a shell command (`--no-verify`, `-n`, force-push, `core.hooksPath`, `LEFTHOOK`, secret-file names, recursive removal of a source directory); `| sh`, `bash <<<`, `bash <<EOF`, `sh -s`, `bash <(…)` and `source <(…)` are blocked; `sh -c "rm -rf src"` is now caught. Closed list of what stays open is in the hook header and `harness-kit-enforcement.md`.
