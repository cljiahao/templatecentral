- Sonar way parity table for the seeded lint configs: `scripts/sonar-parity.tsv` maps each common Sonar rule (TypeScript and Python) to the local rule that catches it, with a status (`covered`, `partial`, `not-covered`) and a reason for the last two. `scripts/check-sonar-parity.sh` reads the three ESLint flat configs and the FastAPI ruff settings statically (no install, scanner, login, key or network) and fails closed. It proves every mapped rule is enabled at error level for ordinary source files in every stack of its language; a block it cannot prove covers all source files or only tests, a global ignore of a source folder, and any spread, call or reference that is not a known preset or constant all fail. A rule that needs type information cannot be `covered` unless every TS stack lints with types. ESLint blocks follow JavaScript object order (a `rules` key replaces an earlier spread's rules), type awareness is read from `parserOptions` for all source files only, and the last block that covers every source file wins. Ruff selectors resolve by linter prefix (`S` is bandit, never `SIM`), and `extend`, dotted keys, a sibling `ruff.toml` and `explicit-preview-rules` are read or raise; `..` paths are never test or tooling paths, and config-file ignores count only at the project root. `pyproject.toml` is read by one strict TOML-subset scanner (tables, dotted keys and headers, basic and literal strings, multi-line arrays, comments, booleans) that raises on duplicate keys, a table defined twice, multi-line strings, undecoded escapes and inline tables where a table is expected; `lint.preview` overrides the top-level `preview`, a ruff selector must be an exact linter or the `PL` group, only root-anchored `dist`/`build`/`out` ignores count as tooling, duplicate ESLint option keys follow last-wins, and a spread in `languageOptions` is reported once, naming the block. Ruff `select`/`ignore` specificity, per-file-ignores and preview-only rules are followed. Preset snapshots in `scripts/sonar-parity-presets/` each carry a `# pin:` line checked against `skills/scaffold/shared/versions.txt`; `scripts/regen-sonar-parity-presets.py` rebuilds them from installed packages. `sonar-rules.tsv` holds public Sonar metadata (type, title, Sonar way) the table is checked against; rows whose key is not in it say `unverified:`. `scripts/check-sonar-parity.test.sh` has a failing case and a clean control for each fail-open form. Not wired into CI yet; the check currently reports S108 and S905 (Next.js) and S4204 (NestJS), where a seeded config does not enable the mapped rule at error level.
