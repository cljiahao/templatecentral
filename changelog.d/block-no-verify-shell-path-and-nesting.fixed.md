- `block-no-verify.sh` no longer parses shells inside shells. The verdict is the union of two scans and the hook blocks when either blocks: the command as written (always judged, so a shell or `eval` word that is only an argument of a git command, as in `git commit -m eval -n`, cannot hide a bypass) and, only when a shell (`sh`, `bash`, `zsh`, `dash`, `ksh`, `ash`, any path such as `./sh`, `~/bin/sh` or `/usr/bin/env bash`) is followed later by an option holding `c` (`-c`, `-lc`, `-c'...'`, `-c$'...'`) or `eval` is in command position, the flattened text (quotes and backslashes dropped, each wrapper word a command separator), which blocks a forbidden command at any nesting depth. Text inside a real wrapper is blocked even when only quoted (`bash -c 'echo "git commit -n"'`). Only a wrapper command over 4000 bytes is blocked as too long to judge (the worst 3.8 KB wrapper measures about 0.52 CPU seconds); prose that merely names a shell (a commit message, a heredoc, a PR body) has no size gate, and long commands with no wrapper now judge in linear time (about 0.15 CPU seconds at 17 KB and 0.36 at 68 KB, from up to 38 seconds).
