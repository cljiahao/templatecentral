- `block-no-verify.sh` no longer parses shells inside shells. A shell (`sh`, `bash`, `zsh`, `dash`, `ksh`, `ash`, any path such as `./sh`, `~/bin/sh` or `/usr/bin/env bash`) followed later by `-c`, or `eval`, makes the command a wrapper; its quotes and backslashes are dropped and each wrapper word becomes a command separator, so a forbidden command is blocked at any nesting depth. Text inside a wrapper is blocked even when only quoted (`bash -c 'echo "git commit -n"'`), and a wrapper command over 1500 bytes is blocked as too long to judge, which keeps the hook under 1 CPU second.
